# yt-dlp Thin Wrapper with Auto-Provisioning

Status: Accepted, except its auto-provisioning, which ADR-0036 removed: yt-dlp and ffmpeg come from `$PATH` only.

Lum's `yt` subcommand shells out to `yt-dlp` as a thin wrapper, constructing args for four user-facing commands (`audio`, `video`, `album`, `rss`): the first three map to audio, video, and album/playlist downloads, and `rss` resolves a link to its channel feed (ADR-0013). yt-dlp is auto-provisioned: if not found on `$PATH`, lum downloads the latest release binary to `data_dir()/deps/yt-dlp` with co-located state in `data_dir()/deps/yt-dlp.json` (version string + last-checked timestamp). The auto-provisioned copy is re-checked against the GitHub latest release no more than once per 24 hours; if a newer version exists, lum replaces it. The system copy on `$PATH` is never version-policed. aria2c is dropped entirely — yt-dlp's native `--concurrent-fragments 8` replaces it since YouTube uses DASH/HLS fragments where aria2c's per-file split settings were ineffective. ffmpeg is provisioned on demand too, but it is refreshed by age, not by version, since its builds are rolling releases (ADR-0009). Output directories are set via yt-dlp's `-P` flag rather than `chdir`. Video quality defaults to `bestvideo[height<=1080]+bestaudio/best` with an optional `--height` flag instead of probing display resolution. `--replace-in-metadata` regex passes clean YouTube title junk. There is no default rate limit, no `--embed-*` post-processing, and no `--tmp` debug flag.
