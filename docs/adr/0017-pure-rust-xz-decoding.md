# Pure-Rust XZ Decoding

## Status

Accepted

## Context

Tool and ffmpeg tar.xz extraction used `xz2`, pulling in the native `lzma-sys` build dependency. The existing `zip` dependency already uses `lzma-rust2`. Blessed.rs lists no XZ-specific recommendation.

## Decision

Use `lzma-rust2::XzReader` for both tar.xz consumers, with the direct dependency enabling only `std` and `xz`. Keep single-stream decoding (`allow_multiple_streams = false`), matching the previous decoder configuration.

Reuse the decoder selected by `zip` rather than introducing another compression implementation. Archive selection, staging, executable permissions, and installation paths remain unchanged.

## Consequences

The workspace no longer needs `xz2` or `lzma-sys`; this removes the native liblzma build edge, not all native dependencies. Other dependencies can still enable additional `lzma-rust2` features through Cargo feature unification.

A pinned CRC64 tar.xz fixture generated by the independent system `xz` encoder covers both extraction paths and corrupt-header rejection. Tests do not require the system encoder.
