# Tray

lum's tray icon, shared by `lum radio`, `lum net on` and, on macOS, `lum display`. This file covers how it is hosted, built and drawn. What the radio's items do is in `src/radio/README.md`, the display's lines in `src/display/README.md` and shaping's in `src/net/README.md`. Why it works this way is in ADR-0022 and ADR-0033.

## Hosts

- While a station is loaded, its runner hosts the tray (`host`): the radio's menu, and above it the status lines while the status tray is up.
- Otherwise the status tray does (`host_status`, behind the hidden `__status_tray` command, in `status.rs`): an icon whose menu holds only the status lines. `lum display off` (macOS) and `lum net on` (Linux and macOS) start it with `status::show`, in a process group of its own, so that Ctrl+C or a closed terminal does not take the icon down while shaping is still on. It holds a lock on `status-tray.lock` in lum's state folder, so there is only ever one. It hides while a station's tray shows the lines, and exits once HiDPI is back on everywhere and shaping is off. A tray that leaves checks once more after releasing its lock and starts a new one if something is in force again, so a command that raced its exit still gets an icon.
- The watch runs every 2 seconds (`WATCH_EVERY`): on macOS on the event loop's timer, on Linux by timing out of the wait for menu events. Windows has no status lines and no watch. What the lines say is read at most every 10 seconds (`READ_EVERY` in `status.rs`): the monitors' modes, and on macOS whether shaping is still on, which asks `ifconfig`, are not worth reading every 2 seconds. A station's tray asks whether the status tray is up and, while it is, reads the lines through a cache of its own. Nothing passes between the processes. The status tray doesn't create its icon until it has something to show, so it never flashes up only to hide.
- The host's main thread owns the tray and every menu object. A station's supervisor runs on a worker thread and only touches `Playback`; see `src/radio/README.md`.
- Linux uses tray-icon's `ksni` backend: StatusNotifierItem over D-Bus, pure Rust, no GTK. It needs a tray host. KDE, Xfce and most bars have one; stock GNOME needs the AppIndicator extension. Without a host the icon is simply invisible. Do not switch to tray-icon's default backend: it links GTK 3, and then every lum command would need GTK 3 installed just to start. The backend can only mark a hidden icon passive, which a host may ignore, so on Linux the status tray takes its icon down while it hides and builds it again when it shows (`serve` in `mod.rs`).
- Windows and macOS run a `winit` event loop on the main thread (`mod.rs`). macOS uses the Accessory activation policy, so there is no Dock icon.
- `$LUM_NO_STATUS_TRAY` is a test hook: it keeps `status::show` from starting the status tray, so the tests of `lum net on` put no icon on the desk.

## Menu

- The status lines are disabled items at the top: one for each monitor with HiDPI off, worded as `lum display status` prints them, then one for shaping, `Shaping on for eth0 since 2026-11-12 20:00`. A separator divides them from the radio's items. The tooltip has a line for each state too: the station, `lum display: HiDPI off` and `lum net: shaping on`.
- Lines are inserted and removed in place: muda carries every change to a `Menu` over to the menu on screen, and on Linux the icon and tooltip update that follows has the backend send the menu again.
- Clicking the icon itself is not a portable gesture across tray hosts, which is why everything is a menu item. The status lines are information only: switching shaping off needs sudo, and sudo needs a terminal.

## Icon

- The icon is drawn in code (`icon.rs`), so there is no image asset to ship: a small radio while a station is loaded, a monitor while HiDPI is off or shaping is on, and with both, a smaller radio over the monitor's bottom-right corner, the way SF Symbols draws its badges. The monitor around the radio is cut away with a one-unit gap, and it drops its stand, which the radio would cut in two. It is always one square icon.
- The monitor's screen says which: hollow for HiDPI off, filled in blue for shaping (`Look.shaping`). Fill against outline is the difference that survives at 16 px. Shaping draws the monitor whether or not HiDPI is off, so with both in force the screen is lit, and the menu and the tooltip say what is on. The radio never goes inside the screen: at 16 px it is a smudge there. It stays in the corner, with its antenna cut out of a lit screen as it is out of a hollow one.
- The radio's antenna is up while playing and folded away while paused, so the state shows in the silhouette and not only in the colour (a template has no colour, and green against grey is a weak cue for colour-blind users). The monitor's only state is its screen. A playing radio is green, a lit screen is blue and nothing else is coloured, so green means playing.
- The icon has to read on any panel, light or dark, because the host paints it over a panel we cannot see. The colour ink uses mid-tone fills, and a test holds them, the blue included, above WCAG's 3:1 contrast floor for graphics against real dark and light panels. The speaker, the knobs and a hollow screen are holes, so they take the panel's own colour, and a faint white rim around the outside keeps the icon visible on mid-tone panels while vanishing on light ones. macOS gets a black template image instead, which the system tints for the menu bar (`with_icon_templated`); that is why the state also changes the shape and, in the template, the opacity. A template has no colour, so while the radio plays or the screen is lit macOS gets the menu bar ink (`Ink::MenuBar`): lum asks the icon's button for its effective appearance, which follows the wallpaper as well as the system setting, and draws the monitor black or white as the template would be, with the radio in Apple's accessible system green for that appearance (`#248a3d` light, `#30d158` dark) and the lit screen in Apple's system blue (`#007aff` light, `#0a84ff` dark), both held above 3:1 on the menu bar by a test. The watch asks again every 2 seconds and redraws on a change.
- The geometry sits on a 16-unit grid so the main edges stay crisp at the common 16 px tray size. There is no preview tool in the repo: when you change the drawing, composite `icon::rgba` over a dark and a light panel at 16, 24 and 32 px and look at it; thin shapes that look fine at 64 px turn to mush at 16.
